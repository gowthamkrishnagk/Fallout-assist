FalloutAssist knowledge routing graph

For each incoming Jira ticket, the graph follows this route:

  1. 1. Retrieve local top K matchesSemantic and keyword search run together to find relevant Jira history and SOP evidence.
  2. 2. Retrieve Rovo MCP top K matchesBy default, MCP search also runs even when local matches are strong. FalloutAssist keeps useful results from both sources, removes duplicates, combines their ranks and runs one AI relevance assessment.
  3. 3. Ask the Rovo agentIf local plus MCP evidence is still insufficient, the agent receives the ticket and available evidence. FalloutAssist checks citations and any new Jira sources before using the proposal.
  4. Apply the evidence gateMissing support, conflicting fixes, or unverified claims go to manual review. Only supported suggestions continue.

Strong combined evidence skips the Rovo agent. In Settings, turn off “Always search local + Rovo MCP” to use local-first fallback instead. Local-only mode and approved saved fixes retain their explicit shortcuts. Each search runs once within its time limit. Medium evidence remains Medium and requires review; Rovo failures are reported separately.

Agents
By default, the LangGraph combines local top K and Rovo MCP top K results for a Jira ticket. The Rovo agent investigates only when the combined evidence is insufficient.

      
Rovo MCP search
Finds Jira candidates alongside local retrieval by default. FalloutAssist removes duplicate tickets and reranks the combined evidence. Settings also allow local-first fallback.
Rovo agent (A2A)
Investigates only after local plus MCP evidence remains insufficient. Its cited proposal is checked before it can support a suggestion.
Connect the Rovo account below to use this fallback or request a separate preview.
FalloutAssist API for another agent
Provides FalloutAssist and Rovo knowledge proposals to a downstream agent. It does not execute Jira actions.
Configure its API key under Configurations. See the API instructions in the app README.

      
Connect Rovo agent (A2A)
Connect Atlassian Rovo to generate its own resolution from historical Jira matches. The existing Rovo search connection is separate.
